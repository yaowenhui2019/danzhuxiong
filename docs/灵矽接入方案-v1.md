# 灵矽接入方案 v1（已查证）

> 结论：**A 方案可行，且不需要真实硬件。** 只需你提供一个 apikey。
> 查证时间：2026-10-25 23:35，全部结论来自灵矽官方文档站 linx.qiniu.com/docs/xrobot

---

## 一、查证结论（这几条决定了架构）

| # | 事实 | 来源 |
|---|---|---|
| 1 | 灵矽**没有**独立的 ASR / TTS HTTP 接口，语音能力只在设备 WebSocket 会话里 | /api/others、/api/voice-clone、/api/llm 均无；/api/agent 只有配置字段 |
| 2 | 设备端协议：`wss://xrobo-io.qiniuapi.com/v1/ws/`，Header 带 `Authorization: Bearer`、`Device-Id`(MAC)、`Client-Id`(UUID)、`Protocol-Version: 1` | /platform/websocket |
| 3 | 上行音频支持 **PCM 16k/16bit/单声道**（frame 20ms = 320 samples），下行 TTS **只给 Opus** | /platform/websocket §3、§4 |
| 4 | 服务端下发：`stt`（识别文本）、`tts`（start/stop/sentence_start）、二进制 Opus 音频帧 | /platform/websocket §6 |
| 5 | **虚拟设备可自行注册**：`POST /xiaozhi/device/preregister {agent_id, mac_addresses}`，不需要真实硬件 | /api/device §4 |
| 6 | 智能体可 API 创建：`POST /xiaozhi/agent`，可指定 `systemPrompt` / `ttsVoiceId` / `llmModelId` | /api/agent |
| 7 | 若配「第三方业务系统接入」，灵矽把你的服务当大模型，用 SSE 回文本，**并且 SSE 里可以指定 `voice_type`** → 每条回复可换音色 | /guide/third-app §2.4 |
| 8 | 音色库：`GET /v1/voices` | /api/others |

第 5 条是转折点：**我们可以在后端伪造一台设备，用 WebSocket 连上灵矽**，从而白嫖它的 ASR 和 Opus TTS。

## 二、三级接入方案（按风险从低到高，按顺序做）

### A1 · 只借灵矽的耳朵（**今晚的主线**）

```
小游戏 → 上传录音 → 我的后端（虚拟设备） → WSS 灵矽 → stt 文本
                                                    ↓
                                          游戏引擎 → 本地 edge-tts 出 5 条声线 → 小游戏
```

- 用到的灵矽能力：**设备接入协议 + ASR + 智能体**
- 不需要：公网地址、业务服务配置、音色库
- 依赖：一个 apikey + 一个 agent_id（可以我用 API 现建）+ 一个虚构 MAC（我自己填）
- 工作量：**约 2 小时**（WS 客户端 + PCM 分帧 + opus 忽略）

### A2 · 让灵矽连嘴也管（加分项，A1 跑通后再上）

配「第三方业务系统接入」，灵矽回调我的 SSE 接口，我在 `details` 里指定每条回复的 `voice_type`：

```
data: {"event":"message","type":"chat","session_id":"xxx",
       "details":{"answer":"我是预言家，昨晚验了3号，是狼。",
                  "tts_provider":"huoshan","voice_type":"BV0xx_streaming"}}
```

- 收益：5 个 AI 各用一条**灵矽音色库**里的声线，故事更硬（"音色来自灵矽"）
- 代价：要公网地址（cloudflared 隧道）+ 灵矽后台配置业务服务端点 + Opus 解码回 mp3
- 工作量：**约 2 小时**，且有配置权限的不确定性

### B · 完全本地兜底（保险绳）

faster-whisper 做 ASR + edge-tts 做 TTS。**零 key、零费用、已实测**。
用途：A1 卡住时立刻切换，保证 demo 一定跑得起来。

## 附：虚拟设备的 hello 报文（我准备发的）

```json
{
  "type": "hello",
  "version": 1,
  "features": {"mcp": false},
  "transport": "websocket",
  "audio_params": {
    "format": "pcm",
    "sample_rate": 16000,
    "channels": 1,
    "bit_depth": 16,
    "endianness": "little",
    "frame_duration": 20,
    "frame_size": 320,
    "sample_format": "signed_int16",
    "play_buffer_duration": 1000
  }
}
```

握手成功后发：

```json
{"session_id": "<上一步返回>", "type": "listen", "state": "start", "mode": "manual"}
```
然后连续发二进制 PCM 帧（每帧 320 samples × 2 bytes = 640 bytes），说完发 `{"type":"listen","state":"stop"}`。
